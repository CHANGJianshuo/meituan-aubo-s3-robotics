# TF_CONVENTIONS —— 坐标系、TCP 与工位约定

> 状态：**设计约定（草案）**。除 `base_link`/`tool0`/`T0`/`P1`/`P2`/`P3` 的**命名**外，
> 所有数值偏移、旋转、TCP、负载、接触行程**一律待实物标定**，未标定前不得作为真实运动默认值。
> 依据：`docs/architecture/AUBO_S3_ROS2_状态机与接口技术设计_v0.1.md` §5.3。

---

## 1. 坐标树（逻辑结构）

```text
world                              # 全局参考；仿真可为仿真世界原点
├── base_link                      # S3 底座，所有业务位姿的最终解析目标
│   └── ...（J1..J6 连杆链，由 URDF 提供）
│       └── tool0                  # 法兰面（厂商定义）
│           └── hook_tcp           # V1 / V2 各自的工具中心点，分别标定
├── table_frame                    # 桌面/底图参考
│   ├── T0_frame                   # 基础任务目标位
│   ├── P1_frame                   # 序列任务第 1 位
│   ├── P2_frame                   # 序列任务第 2 位
│   └── P3_frame                   # 序列任务第 3 位
└── battery_<id>_frame             # 由感知发布的动态观测坐标系
    └── ring_frame                 # 提环抓取参考坐标系（相对本体固定定义）
```

**硬性规则：**

1. 所有业务位姿最终必须能转换到 `base_link`；变换超时或数据过期时**拒绝生成运动目标**。
2. **腕部相机不得挂在 `world` 的静态分支下**，必须按真实安装位置挂到机器人运动链中，否则机器运动时相机外参会失真。
3. `battery_<id>_frame` 为**观测得到**的动态坐标系，不得以仿真 Ground Truth 冒充视觉识别结果。
4. 规划针对 `ring_frame` 而非电池主体几何中心；接合确认为真后才允许把电池作为附着碰撞体加入规划场景；释放分离完成后必须更新规划场景，禁止在附着模型仍存在时规划撤离路线。

## 2. 关键坐标系定义

| 坐标系 | 定义 | 来源 | 状态 |
|---|---|---|---|
| `base_link` | 机械臂底座坐标系，厂商定义 | URDF | 待旧 `mtc_description` 源码补齐后核实 |
| `tool0` | 法兰面坐标系，厂商定义 | URDF | 同上 |
| `hook_tcp` | V1/V2 各自的工具中心点 | **实物标定** | ❌ 未标定（V1/V2 必须分别标定） |
| `ring_frame` | 提环局部抓取参考坐标系 | 感知 + 标定定义 | ❌ 轴向定义待明确（见 §2.1） |
| `table_frame` | 桌面参考 | 底图尺寸 + 现场标定 | ❌ 未标定 |
| `T0/P1/P2/P3_frame` | 固定工位目标位 | 现场标定 | ❌ 未标定 |
| `battery_<id>_frame` | 电池本体实时位姿 | 感知 | ❌ 感知节点未实现 |

### 2.1 `ring_frame` 轴向定义（待团队确认，**当前为提案**）

提环是一个带孔的薄壁结构，其抓取参考坐标系必须唯一确定，否则 V1 侧向穿环与 V2 上方插入无法共用同一契约。提案：

| 轴 | 提案定义 | 需要现场确认的原因 |
|---|---|---|
| `+Z` | 提环平面法向（穿环/插入方向） | V1 侧向穿环与 V2 上方插入的“插入轴”是否可统一为同一轴 |
| `+X` | 提环长边方向（开口 50 mm 方向） | V1 钩头宽度约 40 mm 的回转余量依赖该轴 |
| `+Y` | 由右手定则确定 | — |
| 原点 | 提环孔几何中心 | 需与实际 CAD/道具一致 |

> ⚠️ 上述轴向**未经实物验证**。在标定完成前，`ring_pose` 只能用于几何可视化与仿真，**不得**驱动真实运动。

## 4. 工位与目标

| 目标位 | 用途 | 规则 |
|---|---|---|
| `T0` | 基础任务唯一目标位 | `MODE_BASIC` 的 `ordered_colors` 必须恰好 1 项 |
| `P1` | 序列任务第 1 位 | 对应 `ordered_colors[0]` |
| `P2` | 序列任务第 2 位 | 对应 `ordered_colors[1]` |
| `P3` | 序列任务第 3 位 | 对应 `ordered_colors[2]` |

`target_slot` 只允许 `T0/P1/P2/P3` 四个字符串，其他取值一律拒绝（`INVALID_TASK=100`）。

## 5. 单位约定

| 量 | 单位 | 字段示例 |
|---|---|---|
| 位置 | 米 (m) | `geometry_msgs/PoseStamped` |
| 姿态 | 四元数 | 同上 |
| 关节角 | 弧度 (rad) | `ExecuteJointMove.target_rad` |
| 关节角速度 | rad/s | `actual_velocity_rad_s` |
| 时间（Action 超时） | 毫秒 | `ExecuteTask.timeout_ms` |
| 时间（稳定性观察） | 秒 | `placement_stability_sec` |
| 颜色 | 数值枚举 | `COLOR_RED=1 / BLUE=2 / YELLOW=3 / GREEN=4` |

> ⚠️ 交接文档中的历史实测数值（角度、速度）以**度**为单位记录。本工程内部**统一使用弧度**；与文档对照时必须显式换算，避免单位混淆。
