# 10/12 D435i / V1 现场标定 SOP

本流程用于任务书第 05 项。实物采集尚未执行。机器人运动由现场指定操作人员按团队现场流程完成；标定人员记录和复核。

## 0. 建立记录目录与冻结安装

在自己的开发工作空间运行，不在只读驱动验证目录生成文件：

```bash
mkdir -p runtime_logs/calibration/{device,handeye,tcp,table,validation}
```

记录机器人模型提交、相机序列号/固件/SDK/Wrapper、工具 V1 装配版本、日期、操作与记录人员。拍摄相机支架、法兰转接件、舌规工作点、底座与工作台/底图固定情况。重新装配或松动后，对应标定需复核。

验收误差阈值由规划/机械/视觉按实物配合余量共同确认，分别记录位置 m、姿态 rad，不凭软件默认值宣称通过。

## 1. 只读核验模型与相机参数

按 [交接主文档](../../TF_AND_CALIBRATION_HANDOFF.md) 第 7 节收集 ROS graph 和 TF 图，核对实际 Planning Frame、`wrist3_Link`/`ee_link`、camera_link/optical frame。用 [官方参数流程](D435I_OFFICIAL_PARAMETERS.md) 导出 CameraInfo 和内部外参。

常提供的 fake 材料已确认规划 `world`、末端 `ee_link`、world→base 为固定单位阵；[核验及规划参数映射](FAKE_RUNTIME_AUDIT.md) 不替代真实部署检查。交 V1 TCP 时保存 `T_ee_link_TCP`，规划器已经补偿该偏置；先处理采集 stamp 与历史动态 TF，当前 backend 的 latest 查询不能作为移动相机的时间同步方案。

确认实际图像尺寸、rectified/raw、深度编码/比例、深度是否对齐彩色、采集 stamp 与 ROS 时基。记录后再决定要不要重新标定内参；已有设备参数不意味着安装外参完成。

另记录：机身标签型号（D435i 与 D435if 深度零平面分别为玻璃后 4.2 / 4.7 mm）；`robot_description` 哈希及 `tf2_echo wrist3_Link ee_link` 读数；法兰上标记的 F +X 物理特征（如定位销孔）及其在 RViz 中对应的 `wrist3_Link` 轴向。对齐到彩色的深度图属于彩色光学系，视觉输出的 frame_id 应与之一致。

## 2. 采集 eye-in-hand 外参

固定一块尺寸/角点定义已知的标定板在台面，板在整个采集中保持不动。由孙浩然提供板在选定光学系 C 中的完整 `T_C_board`，确认角点顺序、单位和图像对应流。

选定末端参考系 E 并始终使用同一个名称。每组保存：原始图像、CameraInfo、采集 stamp、该时刻 `T_B_E`、`T_C_board` 和图像质量/重投影误差。模板：[handeye_samples.csv](handeye_samples.csv)。

建议采集约 15–20 个有效不同姿态作为起点，这是采集建议，不是比赛硬指标。应包含不同旋转轴和视角、合适距离，并保留额外未参与求解的验证视角；仅平移或始终绕一个轴可能无法充分约束外参。数量不能替代运动激励和质量检查。

眼在手上的关系为：`T_B_E,i × T_E_C × T_C_board,i = T_B_board`（板固定）。解算程序必须核对返回的方向和 E/C 定义；不只看“求解成功”字样。当前交付包含转换与拒绝校验工具，**没有实现手眼参数求解器**；求解需要真实数据和核验过的算法/软件，由本标定职责后续完成。

保存外参、误差、样本筛选、算法/版本、方向与 frame、日期及安装照片。CAD/尺量结果标 ESTIMATED；完成实测与独立验证后再标 MEASURED。

## 3. 标定 V1 TCP

先与机械/规划人员定义 TCP 是舌规哪个工作点，以及工具坐标轴对应进入/上提/退出方向。不能直接采用旧零 TCP，也不能采用 V2 值。

若现场采用固定点/pivot 方式，在不同末端姿态下让同一个工具参考点对应同一个固定点，保存 `T_B_E,i` 与接触一致性证据。关系为 `R_B_E,i × p_E_TCP + p_B_E,i = p_B_fixed`，需要足够不同姿态使系统可解。模板：[tcp_samples.csv](tcp_samples.csv)。这类方法求的是 TCP 位置；TCP 朝向需另外按舌规 CAD/轴向与现场方法确定。

保存 `T_E_TCP` 的完整平移和旋转，并以独立姿态复核工作点位置及工具朝向。若参考系由 wrist3 改为 ee_link，应用模型/实际固定变换转换数值，不能只修改 frame 标签。

## 4. 台面、底图与 T0

定义台面原点、法向和轴向，记录 `T_B_table`；多点测量应能检查平面与方向。记录官方底图尺寸、放置位置、固定方式及 T0 中心/朝向/高度。

确认目标位表达的是电池本体目标、提环目标还是 TCP 目标。电池落座高度、提环高度和舌规接合偏置需分别记录；P1/P2/P3 用相同规则。更新 [measurement_inventory.csv](measurement_inventory.csv)，未测项保持 UNKNOWN。

## 5. 独立验证与移交

使用未参加求解的点/姿态复核相机变换、TCP 与 T0。记录预测与参考位置、位置误差 m、姿态误差 rad、阈值、是否通过及照片/数据。模板：[validation_points.csv](validation_points.csv)。四元数 q/-q 等价，姿态比较不要直接比较元素符号。

用卷尺/量块从**前玻璃**量目标距离来核对深度时，按数据手册 Table 4-16 加 4.2 mm（D435i）才等于相机深度值；这个修正只做一次。外参已把深度原点放在玻璃后 4.2 mm，不要再对相机深度值或外参重复补偿。

逐项检查：相机随机器人运动时末端安装外参稳定；相机观测按采集时刻转到规划系；ring_pose 轴向和 V1 进入方向一致；T0 姿态和高度有依据；TF/标定失效会被适配器拒绝。

最后向规划与集成移交参数版本、frame、单位、时间、误差和失效条件。TF 可达并不证明精度合格。当前文件中的现场步骤均为 NOT RUN，不能作为实测成功证据。
